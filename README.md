# drive-logger-ios

自分用の iPhone 走行ロガー。GPS・加速度・回転・気圧を記録し、走行が終わったら自宅の MiniPC で動いている
[国道制覇マップ](https://github.com/Yzvica/National-Route-Conquest-Map) へ自動で送る。

- 対象: iOS 16 以降(ログ専用の iPhone X を想定)
- 画面を消しても、ほかのアプリを開いても記録を続ける(位置情報を「常に」許可する)
- 念のため、記録中は画面が自動で消えないようにしてある(設定の「記録中は画面を消さない」。既定はオン。止めると元に戻る。電源ボタンで消すのは自由)
- 走行ごとに `Documents/logs/<yyyyMMdd-HHmmss>/` に保存する。「ファイル」アプリの「このiPhone内」→「走行ロガー」からも見られる

## 記録するファイル

| ファイル | 中身 | 頻度 |
| --- | --- | --- |
| track.gpx | 精度 50m 以内の位置・高度・時刻・速度。地図に送る | 1Hz |
| location.csv | 位置のすべて(精度・速度の精度・進行方向を含む)。GPS の速度が来ないとき(トンネルなど)は `speed_ms` を空にし、位置の動きから推定した速度を `speed_est_ms` に書く | 1Hz |
| motion.csv | 加速度(重力を除く、g)・重力の向き・回転(rad/s)・姿勢(クォータニオン)・方位 | 50Hz(設定で 25/100) |
| pressure.csv | 気圧(hPa)・記録開始からの相対高度(m) | 約1Hz |
| meta.json | 端末・時刻の対応・距離・目印(目印 / 動画の同期)・送信状況 | - |
| evaluation.json | 運転の評価(停止後に計算。DriveLog の evaluation.json と同じ形、`source: "iphone"`) | - |
| replay.csv | 地図の運転リプレイ用。0.5 秒ごとの `unix_s,lat,lon,kmh,lon_g,lat_g,jerk`(評価と同じ車の向き。G は 0.5 秒の中で絶対値が一番大きいもの、躍度は一番大きいもの)。評価と一緒に作り、地図に送る。前からある走行は振り返りを開いたときに作って送る | 0.5秒 |
| weather.json | 走ったときの天気(地図サーバーが Open-Meteo から取ったものを、ログの詳細を開いたときに受け取る。飛行機はなし) | - |
| amedas.jsonl | 記録中に取った最寄りのアメダス観測所の実測。1行 = 1観測所の1時刻(`t` 日本時間・`code`・`name`・`km` 観測所までの距離・`precip10m`・`precip1h`・`temp`・`humidity`・`wind`・`windDir` 16方位の番号)。ネットにつながっていたときだけ | 10分ごと |
| rain_radar.jsonl | 記録中に取った気象庁の雨雲レーダー(高解像度降水ナウキャスト)のタイル。1行 = タイル1枚(`v` 時刻 UTC・`z/x/y`・`core` 地図に映るタイルか・`png` base64。降水の無いタイルは `png` なし)。ネットにつながっていたときだけ | 5分ごと |

時刻はどれも UNIX 秒(UTC)。

## 記録の手順

1. DJI の録画を先に始めてから、iPhone を DJI Mic の近くで「記録開始」(同期の合図が動画に入る)
2. DJI Mic のマイク表示・SD の空き・電池を確認
3. 空が見える所で、GPS 精度が ±10m 前後になってから発進
4. 停止は走り終えてから(途中で押すと走行が分かれる)。「停止」を押すと、止める直前にもう一度同期の合図を出す。DJI の録画はそのあとで止める

記録画面にも同じ注意書きを出す(記録していないときは折りたためる一覧、記録中は 4 だけ)。

## 記録画面の地図

- 左上で地図を切り替える: Apple 標準 / Apple 航空写真 / 国土地理院 標準・淡色・写真(地理院タイル。右下に出典を表示)
- 右上のボタンで「追尾しない → 北が上で追尾 → 進行方向が上で追尾」を切り替える。指で動かすと追尾が外れるので、ボタンで戻す
- 選んだ地図と向きは覚えておく

## 合図の音

消音モードでも鳴る(音楽など、ほかのアプリの音は止めない)。鳴った時刻は meta.json の `markers` に残る。

| いつ | 音 | meta.json |
| --- | --- | --- |
| 記録開始・停止の直前(自動)・「同期」ボタン | 2000Hz を 0.12 秒 × 3 回(間は 0.08 秒の無音。全体 0.52 秒)。画面も光る | `kind: "sync"`。時刻は 1 回目の音の出だし |
| 「目印」ボタン | 1500Hz を 0.08 秒 × 1 回 | `kind: "mark"` |
| 記録停止 | 800Hz 0.15 秒 → 無音 0.08 秒 → 600Hz 0.2 秒 | 残さない |
| 急ブレーキ(記録中のサポート) | 700Hz → 480Hz(下がる) | 残さない |
| 急加速 | 480Hz → 760Hz(上がる) | 残さない |
| 急ハンドル | 900Hz を短く 2 回 | 残さない |
| そのほかの急な操作 | 600Hz を短く 1 回 | 残さない |
| 止まり際のカックン | 380Hz を 0.18 秒 | 残さない |

サポートの音は同期音と取り違えないよう、どれも 1000Hz 以下・音量も小さめ。設定で切れる。

DJI Mic で同期音を拾えば、動画の音声から 2000Hz の 3 連音を探して、ログと動画の時刻を合わせられる。

## 雨(気象庁の雨雲レーダーとアメダス)

- 記録中、ネットにつながっていれば(テザリングなど)、気象庁の高解像度降水ナウキャスト(約250m・5分おき・強度8段階)を5分ごとに取り、走行フォルダの `rain_radar.jsonl` に貯める(`RainFetcher.swift`)。取るのは通った位置の周りのタイルと、その周り1タイル(動画用の30秒おきの推定で、雨雲の動きを見るため)
- 記録画面に、いまいる場所の雨の強さ(「雨 1〜5mm/h 21:40 時点」)と、この先30分の予測でいちばん強い雨を出す。気象庁のデータが出るのは観測の約1分後で5分おきなので、値は1〜6分前のもの
- つながっていない間のぶんは、つながったときに3時間前まで(気象庁の一覧に残っているぶん)さかのぼって取る。それでも取れなかった時刻は、PC の `FetchRainRadar.bat` が走行後に取る
- `rain_radar.jsonl` は生データと一緒に MiniPC へ送り、PC の `FetchRainRadar.bat` が動画用の雨雲レーダーのデータに取り込む(気象庁の保存期間の約5日を過ぎても使える)
- あわせて、最寄りのアメダス観測所の実測(10分ごとの雨量・1時間の雨量・気温・風)を取り、記録画面に「アメダス 東京(2km) 21:40 / 10分 0.5mm ・ 1時間 1.5mm ・ 12.6℃ ・ 西の風 2 m/s」のように出して `amedas.jsonl` に貯める(`AmedasFetcher.swift`)。雨量は最寄りの観測所、気温・風は気温を測っている最寄りの観測所(40km 以内)。観測所は約17km おきなので、走っている場所そのものの値ではない。つながっていなかった間はさかのぼらない
- 「情報」タブでは、記録していないときも、いまいる場所の雨雲レーダー(実況と60分先までの予測を5分ごとの色の帯で)と、最寄りのアメダスの実測(雨量・気温・湿度・風)を見られる(`InfoView.swift`。開いたときと引っ張って更新。保存はしない)
- 設定の「記録中に雨雲レーダーとアメダスを取る」で止められる。飛行機の記録では取らない。通信量は1時間で1MB ほど
- タイルの読み方は CI で実際のタイルを使って確かめている(`tools/raincheck`)

## 運転の評価(酔いにくい運転)

- 走り終えたら、gbowl-log-formatter の DriveLog と同じ計算(`DriveEval.swift`)で点数・5 項目・点数を下げた出来事を出す。記録画面とログの詳細で見られ、ログの一覧には点数が付く。`evaluation.json` は地図にも送る
- 記録中のサポート(`LiveCoach.swift`): 走りだしてから 1〜2 分で車の向きを合わせ、そのあとは
  - G の点(上が減速・下が加速・左右は体が押される向き。内側の円 0.15G、外側 0.35G)
  - 直近 5 分の点数と、いちばん低い項目を上げるためのひとこと
  - 急な操作の回数(しきい値は走り終えたあとの評価と同じ)と、その音
  - カーブ・停止・発進が終わるたびに、その区間の点数(「右カーブ 82点・小ささ○ ゆっくり◎ 一筆△」)を 3 秒だけ出す(音は鳴らさない。直近 60 秒を 1 秒ごとに採点する)
- 端末を付け直すと(重力の向きが 12° 以上変わると)、向き合わせをやり直す
- 区間ごとの採点(`SegmentEval.swift`、DriveLog の `drive_eval.py` の `segments` と同じ): カーブ(交差点の右左折を含む)・停止・発進を1つずつ切り出し、項目の平均で 0〜100 点を付ける。総合点には入れない
  - カーブ: 横G 0.15G 超を芯に 0.05G まで広げた区間(2 秒以上)。最低速度 25 km/h 未満で向きが 60° 以上変われば右左折。小ささ(最大の横G 0.15〜0.35G)・ゆっくり(Gの変化の速さの最大 1.0〜4.0 m/s³)・一筆(合成Gが途中で落ちてまた上がった量 0〜0.15G)
  - 停止: 停止の直前 3 秒以内の減速(0.03G 超)の始まり〜停止(最長 20 秒)。減速の強さ(0.15〜0.35G)・踏み始め(1.0〜4.0 m/s³)・止まり際(0.5〜4.0 m/s³)
  - 発進: 停止の終わり〜加速が 0.03G を切るか 40 km/h(最長 15 秒)。加速の強さ(0.12〜0.30G)・踏み始め(1.0〜4.0 m/s³)
  - ログの詳細に種類ごとの回数と平均点、点数の低い場面 3 つ(押すとその場面の少し前から振り返りを再生)
- 計算が Python 版と同じかは、CI で `tools/evalcheck` を動かして確かめる

## 振り返り(地図とグラフ)

ログの詳細の「地図とグラフで振り返る」で開く(`ReviewView.swift` / `ReviewMapView.swift` / `ReviewData.swift`)。

- 上は地図。軌跡を速度で色分け(20 km/h まで青 → 40 水色 → 60 緑 → 80 黄 → 100 橙 → それより上は赤)し、点数を下げた出来事をピンで出す
- 下はグラフ 3 段。速度、前後G と横G(2 色で重ねる)、躍度。高度は「G・躍度 / 高度」で切り替える(車以外は速度と高度だけ)。横軸は右上のメニューで時間と距離を切り替える
- リプレイ: ▶ で再生(×1・×5・×10・×30・×60)。丸が向きの矢印つきで地図の上を走り、「追尾」が入っていれば地図がついていく(指で地図を動かすと切れる)。グラフのカーソルと G円(ボウルに乗った球のように、加速すると下・減速すると上・左に曲がると右へ動く。点線は急な操作の 0.35G、尾は直近 4 秒。間引く前の 10 Hz の値を補って動かす)も一緒に動く。再生中にグラフをなぞるとそこから続ける。出来事のボタンはその 5 秒前から等倍で再生する
- カーブ・停止・発進は地図に点数の色(80 点以上は緑、60 点以上は黄、それより下はオレンジ)の小さな丸で出し、押すとその区間の少し前から等倍で再生する。再生中やカーソルが区間の中(と終わってから 3 秒)にあるときは、出来事のボタンの代わりに区間の点数と項目の印を出し、G円の尾の代わりに区間の始めからの軌跡を点数の色で描く(丸く一筆で描けたかが見える)
- グラフをなぞると地図の紫の丸がその時刻の場所へ動き、その時点の値を出す。地図の線をタップすると、そこがグラフで選ばれる
- G と躍度は評価と同じ方法(車の向き合わせ・1 秒ならし)で出す。長い走行は 1,500 点までにまとめ、G と躍度はまとめた中で一番大きいものを使う(山を見逃さないため)
- 高度は気圧の相対高度を GPS の高度(中央値)にそろえたもの。気圧が無いとき、飛行機のとき(機内は与圧されていて気圧が外の高度と合わない)、気圧の変化が GPS の高度の変化の半分もないときは GPS の高度
- 地図のダブルタップして上下の拡大縮小は、記録画面と同じく設定の向きに従う(`OneFingerZoom.swift`)
- CI で `tools/reviewcheck` を動かし、サンプルの走行からデータを作れるかを確かめる

## ナビ(コースの音声案内)

地図(national-route-conquest-map)の「🧭 ナビ・コース」で道筋を出してから保存したコースを、「ナビ」タブで受け取って音声で案内する。
Google マップのリンクを何本も開いたり、経由地ごとに「続行」を押したりしなくてよい。

- 受け取り: 「MiniPC から一覧を読む」→「受け取る」。案内のデータ(道筋と曲がる所)は `Documents/navi/` に保存するので、走行中は MiniPC につながらなくてよい(家の Wi-Fi で受け取っておく)。
- 案内: 交差点で曲がる所・道が変わる所・高速の入口/JCT/出口の手前で「2キロ先」「300メートル先」「まもなく」と読み上げる(速さで距離を変える)。次の案内が 5km 以上先なら「しばらく道なり」。トンネルで位置が来ないあいだは最後の速さで進んだとみなして続ける(最大 5km)。
- 外れたとき: 45m 以上離れた状態が 5 秒続くと「コースから外れました」と言い、Apple の経路(MKDirections、無料・通信を使う)でコースの少し先まで案内する。コースに戻ると「コースに戻りました」。
- 一般道(地図の点線。データにない道)の区間: 300m より長ければ 700m 手前で Apple の経路を取り、それで案内する。
- 画面の下に、残りの距離・今の道と現在地の住所(Apple の住所検索 CLGeocoder。300m 動くか 2 分ごと、通信を使う)を出す。
- 声: 再生用のオーディオ(voicePrompt)で出し、音楽などは小さくする。CarPlay につないでいれば車のスピーカーから出る。**CarPlay の画面に自作のナビは出せない**(Apple の CarPlay ナビ用の許可 com.apple.developer.carplay-maps が要り、有料の開発者登録と Apple の審査が前提。無料の Apple ID では付けられない)。
- 案内の計算は `NaviCore.swift`(Foundation だけ)。`tools/navicheck` で、地図が作った香嵐渓→用賀のコース(高速あり・下道のみ)を走ったつもりで、全部の案内を読むか・外れて戻るか・トンネルでも読むかを確かめる(CI)。

## 地図への送信

- `track.gpx` → `POST /api/inbox?name=<走行ID>.gpx`(地図が国道の判定をする)
- 生データ → `PUT /api/rawlog?session=<走行ID>&file=<ファイル名>`(MiniPC が Google ドライブの `_drivelog` に置く)
- 記録を止めたら、送り終えるまで(最長 15 分)精度を落とした位置の更新を続けてアプリを起こしておく。画面を消しても、テザリングで送れるまで 30 秒ごとに送り直す
- 通信できないときは端末に残し、Wi-Fi やテザリングにつながったとき、またはアプリを開いたときに送り直す
- 送り先は設定画面で変えられる。既定は `http://192.168.11.123:8080`。外出先からは Tailscale のアドレスを使う

## ビルドと iPhone への入れ方(Mac なし・無料の Apple ID)

1. GitHub の Actions「ビルド(署名なし IPA)」が、push のたびに `DriveLogger-unsigned.ipa` を作る(Actions の実行結果の Artifacts から zip でダウンロードして展開する)
2. Windows に [Sideloadly](https://sideloadly.io/) と iTunes(Apple のサイト版)を入れる
3. iPhone を USB でつなぎ、Sideloadly に IPA をドロップし、Apple ID を入れて Start
4. iPhone の「設定」→「一般」→「VPNとデバイス管理」で、自分の Apple ID を信頼する
5. iOS 16 以降は「設定」→「プライバシーとセキュリティ」→「デベロッパモード」をオンにする(初回のみ。再起動が必要)

無料の Apple ID では 7 日で起動できなくなるので、旅行の前に 3(Sideloadly で入れ直す)だけ行う。同じ Apple ID なら 4 の信頼と 5 のデベロッパモードはそのまま残る(ログも消えない)。もし起動時に信頼を求められたら 4 を行う。
