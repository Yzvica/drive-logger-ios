# osmo_telemetry

DJI Osmo Action 6 で撮った動画(`.LRF` または `.MP4`)から、カメラが記録しているテレメトリ(`djmd` トラック)を取り出し、1 フレーム 1 行の CSV に書き出すツールです。

- 使うのは Python 3 の標準ライブラリだけです。外部ライブラリは要りません。
- 読むのはファイル末尾の `moov` ボックスと、djmd トラックのサンプルだけです。動画の本体は読まないので、17 GB の MP4 でも約 12 秒、メモリ約 8 MB で終わります。
- 入力ファイルは読むだけで、変更しません。
- カメラのシリアル番号などの機器情報は出力しません。

> **GPS(緯度経度・速度)は入っていません。** 手元のサンプル(GPS リモコンを付けずに撮影したもの)を調べた結果です。走行経路はアプリ側の GPS ログで記録し、このツールの時刻(`time_utc`)を使って同期させてください。

## 使い方

```
python extract.py DJI_20260417160921_0060_D.LRF
python extract.py DJI_20260417160921_0060_D.MP4 -o out.csv
```

`-o` を省略すると、入力ファイルと同じ場所に `<名前>_telemetry.csv` を作ります。

- 読むのは **LRF で十分**です。LRF の djmd は 29.97 Hz で、姿勢と加速度の更新頻度(30 Hz)と同じです。
- MP4 は 59.94 Hz で、同じ姿勢と加速度が 2 フレームずつ続きます。

## 列の意味

その値が入っていないフレームは空欄になります。

| 列 | 単位 | 意味 |
|---|---|---|
| `frame` | – | フレーム番号(0 始まり) |
| `time_utc` | ISO8601 | 絶対時刻(UTC、ミリ秒まで)。撮影開始時刻 + カメラ内部時刻の経過分 |
| `time_jst` | ISO8601 | 同じ時刻を JST(+09:00)で表したもの |
| `t_video_s` | 秒 | 動画の先頭からの経過時間 |
| `accel_x_g` / `accel_y_g` / `accel_z_g` | g | 加速度。重力を含み、静止時の大きさは約 1。カメラ座標系 |
| `quat_w` / `quat_x` / `quat_y` / `quat_z` | – | カメラ姿勢の単位クォータニオン |
| `gyro_x_dps` / `gyro_y_dps` / `gyro_z_dps` | deg/s | 角速度。カメラ座標系。隣り合う姿勢の差分から計算 |
| `pressure_hpa` | hPa | 気圧(整数) |
| `altitude_m` | m | 気圧から計算された高度(0.1 m 刻み) |
| `iso` | – | ISO 感度 |
| `shutter_s` | 秒 | シャッター速度(露光時間) |
| `shutter_frac` | – | シャッター速度の分数表記(例 `1/625`) |
| `f_number` | – | 絞り(F値) |
| `color_temp_k` | K | ホワイトバランスの色温度 |

## 解釈の根拠と注意点

djmd は protobuf 形式ですが、DJI はスキーマ(`dvtm_ac206.proto`)を公開していません。各フィールドの意味は、実データを見て推定したものです。

| フィールド | 解釈 | 根拠 |
|---|---|---|
| 3.1.2 | カメラ内部時刻 [µs] | フレームごとに 16,683 µs(59.94 Hz)ずつ増え、合計が動画の長さと一致する |
| 3.2.9.1〜4 | クォータニオン (w, x, y, z) | ノルムが 1。`R(q)ᵀ·(0,0,−1)` が加速度の向きと平均 6° で一致したので、カメラ座標系→下向きを z とする世界座標系の回転と判断した |
| 3.2.10.2〜4 | 加速度 x, y, z [g] | 大きさの平均が 1.006 |
| 3.2.3.1 | ISO | 200〜25600 |
| 3.2.4.1 | シャッター速度 | (1, N) の packed varint で、1/N 秒 |
| 3.2.15.1 | 絞り | (N, 10) の packed varint で、F = N/10(f/2.4〜4.0) |
| 3.2.6.1 | 色温度 [K] | 2571〜5709 |
| 3.2.13.3 | 気圧 [hPa] | 1009〜1016 |
| 3.2.13.2 | 高度 [0.1 m] | 気圧との相関が −0.84 で、変化量が約 8 m/hPa(標準大気とほぼ同じ) |

注意点:

- **撮影開始時刻**には `moov/mvhd` の作成時刻を使っています。秒単位なので、ミリ秒以下はカメラ内部時刻の差分だけで決まります。ファイル名の時刻(例 `160921`)とは約 2 秒ずれることがあります。外部ログとは、急ブレーキなどの特徴的なイベントで合わせ込むのが確実です。
- **角速度**は、姿勢が更新されたフレームで「直前に更新された姿勢との差分 ÷ 時間差」として計算しています。MP4 で同じ姿勢が続くフレームには直前の値を入れます。最初の更新までは空欄です。
- **高度**について:
  - カメラは負の高度を 0 として記録しているようで、protobuf ではそのフィールドが省略されます。このツールは、気圧の値があるのに高度が省略されているフレームを 0.0 として出力します。
  - 絶対的な標高ではなく、標準大気から計算した気圧高度とみられます。坂の上り下りの判定などに使う想定です。
  - 標準大気の式による高度より、一律に約 5 m 低く出ています。
- 加速度の軸の向きは、カメラ本体の座標系です。取り付け角は、姿勢(または静止時の重力の向き)から補正してください。サンプル動画はカメラを逆さに取り付けて撮影したもので、映像には回転 −180° が設定されていました。
